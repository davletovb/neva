# Hiyal R0/R5 observed benchmarks — 20 October 2026

**Result:** successfully executed on the *same* GitHub Actions Ubuntu x86-64 runner in
[run #39384593617](https://github.com/davletovb/hiyal/actions/runs/39384593617).
Raw results are preserved in the **hiyal-r0-r5-benchmarks-20261020**
GitHub Actions artifact (30-day retention, until 2026-11-19).
All 60 Rust cases and all Python cases/checkpoints completed without errors.

**Interpretation is constrained:** this is **not a directly matched-work
Rust-vs-Python speedup benchmark**. Archived Python uses an in-memory
`BasicEnvironment.step()` with a mocked `"ok"` LLM; Rust uses a typed
`Counter` and durable fsync-per-step, hash-chained events. Compare
observer-on vs observer-off **within** each engine. Absolute Rust throughput
is lower in this run because its commits perform durable I/O; do not claim
Rust is `Nx` faster based on these numbers.

## Interpretation and remaining scientific work

1. **Within-workload observer overhead** in this measurement grows substantially
   with Python agent count/history size (about 3.9×–10.9×), while native Rust
   JSONL+CSV projection adds roughly 7%–16% wall time atop durable commits.
2. **Absolute observed Python wall times are lower** than Rust here because the
   Python baseline does not fsync every action or persist a complete
   authoritative hash chain. This is not a defect and is not evidence of
   inferior Rust CPU computation.
3. The requested **same-workload cross-language benchmark is still pending**:
   implement parity-checked pure policy/scheduler kernels with the same action,
   observer and durability boundaries, plus isolated cold-start, retained-memory
   and network-bound tier. Do not mark a general cross-language speedup proven.
4. Shared GitHub-hosted runners have noisy neighbors and virtual disks; repeat
   on controlled hardware with pinned governor/storage before making a product
   performance promise.

The one-time benchmark PR and workflow are intentionally separate from normal
Rust CI. No recurring Python CI, no runtime Python dependency, and no
re-activation of archived CI or Dependabot.
